# Tenant Camera Management Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give tenants a first-class `cameras` resource — a real DB table, CRUD API under `/tenants/{id}/cameras`, and UI wiring so the SiteDetailDrawer "ANPR Cameras" tab and MonitoringPage "Cameras & Streams" tab show/manage real cameras instead of synthetic/empty placeholders.

**Architecture:** New `cameras` table (tenant-scoped, RLS, FKs to site/lane/edge-device) following the existing `sites.py`/`gates.py` router pattern: `TenantCtx` dependency, camelCase pydantic schemas, audit log on mutations, `Page[T]` list envelope. Frontend reuses the existing `cameras: CameraHealth[]` collection in `PlatformContext` (populated via `tenantApi.cameras` in `loadTenantData`) plus new context mutations; a `CameraFormModal` handles create/edit inside the site drawer.

**Tech Stack:** FastAPI + SQLAlchemy async + Alembic (raw `op.execute` SQL style), PostgreSQL RLS (`tenant_isolation` policy, `vehicle_app` role), pydantic `CamelModel`; React 19 + TS, `tenantApi` client in `src/services/api/index.ts`.

**Spec:** `SPEC_ANALYSIS_AND_PLAN.md` (gap: cameras honest-empty, §3.4) and `frontend/SYSTEM_ARCHITECTURE_AND_DATABASE_DESIGN.md` §15 (MonitoringPage cameras tab, line ~268), §3 `site_lanes.camera_rtsp_url` (line ~647), §1257 (dual-frame capture → `purpose` field).

## Global Constraints

- Backend enums are **lowercase** (`active`, `disabled`, `provisioning`, `plate`, `overview`) — do NOT use spec's UPPERCASE wire values.
- Response envelope: `Page[T]` `{data, meta:{page,limit,total}}` for lists; bare object for single resource; errors `{error:{code,message}, requestId}`.
- All schemas extend `CamelModel` (`app/schemas/common.py`) — snake_case fields serialize as camelCase.
- Router deps pattern: `dependencies=[Depends(csrf_protect)]` on the router; reads need only `tenant_ctx`; writes add `Depends(require_roles(*WRITE_ROLES))`; mutations call `write_audit(...)`.
- Migration style: raw SQL via `op.execute`, `CREATE ... IF NOT EXISTS` where safe, revision `0009_cameras`, `down_revision = "0008_converge_columns"`.
- RLS policy must use the corrected 0007 form: `current_setting('app.platform_bypass', true) = 'true' OR tenant_id = current_setting('app.current_tenant_id', true)::uuid`.
- `stream_url` scheme must be one of `rtsp | rtsps | http | https`. Do **not** apply the public-IP SSRF check from `webhook_url` — cameras live on private LANs.
- Frontend has **no test runner** — frontend tasks verify with `npm run lint` (`tsc --noEmit`) + `npm run build`.
- `schema.d.ts` is generated by openapi-typescript but there is no npm script — do NOT regenerate it; add hand-written `CameraIn`/`CameraOut` interfaces in `services/api/index.ts` (same convention as `Page<T>`, `InfraHealth`).

## Review Focus

- **RTSP credentials in URL:** `rtsp://user:pass@host/...` is standard; the URL is stored and returned in plaintext to anyone with read access (viewer role + platform admins). UI must mask the userinfo when displaying. Test pins this in Task 8.
- **Cross-tenant FK linking:** `create_gate` never validates that `site_id` belongs to the tenant — a tenant could reference another tenant's site (FK check ignores RLS). Cameras MUST validate site/lane/edge-device ownership via an RLS-scoped select → 404/400. Test pins this in Task 4.
- **Status is administrative, not stream truth:** `active` does not mean video flows (no edge telemetry yet — per scope). `provisioning` is the default; UI must not render "LIVE" for it. Mapper maps provisioning→`DEGRADED`, not ONLINE.
- **Delete cascades:** deleting a site CASCADEs its cameras; deleting a lane/edge-device SETs NULL on cameras. Verify no orphans/500s. Test pins cascade in Task 4.
- **Hand-written API types:** `CameraOut` in `index.ts` must exactly match pydantic camelCase output (`siteId`, `edgeDeviceId`, `streamUrl`, `createdAt`…) — a typo silently yields `undefined`. tsc can't catch it; assert one real field end-to-end in Task 5's manual check.

```sql
CREATE TABLE IF NOT EXISTS cameras (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id uuid NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    site_id uuid NOT NULL REFERENCES tenant_sites(id) ON DELETE CASCADE,
    lane_id uuid REFERENCES site_lanes(id) ON DELETE SET NULL,
    edge_device_id uuid REFERENCES edge_devices(id) ON DELETE SET NULL,
    name varchar(200) NOT NULL,
    code varchar(50),
    stream_url text NOT NULL,
    purpose varchar(20) NOT NULL DEFAULT 'plate',
    status varchar(30) NOT NULL DEFAULT 'provisioning',
    notes text,
    created_at timestamptz NOT NULL DEFAULT now(),
    updated_at timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX IF NOT EXISTS ux_site_camera_code
    ON cameras (site_id, code) WHERE code IS NOT NULL;
CREATE INDEX IF NOT EXISTS ix_cameras_tenant ON cameras (tenant_id, site_id);
ALTER TABLE cameras ENABLE ROW LEVEL SECURITY;
CREATE POLICY tenant_isolation ON cameras
    USING (current_setting('app.platform_bypass', true) = 'true'
           OR tenant_id = current_setting('app.current_tenant_id', true)::uuid)
    WITH CHECK (current_setting('app.platform_bypass', true) = 'true'
           OR tenant_id = current_setting('app.current_tenant_id', true)::uuid);
GRANT SELECT, INSERT, UPDATE, DELETE ON cameras TO vehicle_app;
-- Backfill existing lane camera_url into camera rows (keeps site_lanes.camera_url as legacy/deprecated).
INSERT INTO cameras (tenant_id, site_id, lane_id, name, stream_url, purpose, status)
SELECT l.tenant_id, l.site_id, l.id, l.name || ' camera', l.camera_url, 'plate', 'active'
FROM site_lanes l WHERE l.camera_url IS NOT NULL AND btrim(l.camera_url) <> '';
```

Downgrade: `DROP POLICY IF EXISTS tenant_isolation ON cameras; DROP TABLE IF EXISTS cameras`.
