# Kế hoạch sửa 2 defect trên Mobile Driver App

## 1. Phân tích nguyên nhân gốc

### DEFECT-MOBILE-01 (i18n): Thông báo "Plate already registered" bị hardcoded tiếng Anh khi trùng biển số
- **File**: `mobile/src/components/profile/VehicleModal.tsx` (dòng 72) và `mobile/src/components/views/ProfileScreen.tsx` (dòng 80).
- **Nguyên nhân**: Khi backend trả về HTTP 409 Conflict với JSON `{"error": {"code": "conflict", "message": "Plate already registered"}}`, frontend bắt lỗi `ApiError` và gán thẳng `setErrorMsg(err.message)` mà không map qua từ điển i18n theo ngôn ngữ hiện tại của app.
- **Giải pháp**:
  1. Thêm key `plateAlreadyRegistered` vào `mobile/src/i18n/translations.ts` cho cả 2 ngôn ngữ:
     - `en`: `"License plate is already registered in the system."`
     - `vi`: `"Biển số xe đã được đăng ký trên hệ thống."`
  2. Cập nhật `VehicleModal.tsx` và `ProfileScreen.tsx` để khi gặp `err.code === 'conflict'` hoặc message chứa `plate already registered`, hiển thị `t('plateAlreadyRegistered')`.

### DEFECT-MOBILE-02 (UX): Đăng ký với mật khẩu ngắn hơn 8 ký tự hiện thông báo chung chung "Request validation failed"
- **File**: `mobile/src/components/auth/LoginScreen.tsx` (dòng 22–47).
- **Nguyên nhân**:
  1. Thiếu kiểm tra client-side trước khi submit form cho trường `password.length < 8` ở chế độ đăng ký (`mode === 'signup'`). Mặc dù thẻ `<input>` có thuộc tính `minLength={8}`, submit qua Enter hoặc các trường hợp biên vẫn gửi payload lên server.
  2. Khi backend trả về HTTP 422 `{"error": {"code": "validation_error", "message": "Request validation failed", "details": ...}}`, khối catch chỉ check `invalid_credentials` và `account_locked`, sau đó fallback thẳng vào `err.message` ("Request validation failed").
- **Giải pháp**:
  1. Thêm key `passwordMinLength` vào `mobile/src/i18n/translations.ts`:
     - `en`: `"Password must be at least 8 characters long."`
     - `vi`: `"Mật khẩu phải có ít nhất 8 ký tự."`
  2. Thêm key `emailAlreadyRegistered` vào `translations.ts` (cho trường hợp đăng ký trùng email):
     - `en`: `"This email address is already registered."`
     - `vi`: `"Địa chỉ email này đã được đăng ký."`
  3. Cập nhật `LoginScreen.tsx`:
     - Kiểm tra client-side trong `handleSubmit`: nếu `mode === 'signup'` và `password.length < 8`, gán `setErrorMsg(t('passwordMinLength'))` và `return` ngay.
     - Trong khối catch của `handleSubmit`: nếu `err.code === 'validation_error'` hoặc `err.status === 422`, trích xuất lỗi password để hiển thị `t('passwordMinLength')`; nếu `err.code === 'conflict'` hiển thị `t('emailAlreadyRegistered')`.

## 2. Các file cần chỉnh sửa

1. `mobile/src/i18n/translations.ts`:
   - Thêm các key `plateAlreadyRegistered`, `passwordMinLength`, `emailAlreadyRegistered` vào cả 2 dictionary `en` và `vi`.
2. `mobile/src/components/profile/VehicleModal.tsx`:
   - Thêm xử lý map `ApiError` code `conflict` sang `t('plateAlreadyRegistered')`.
3. `mobile/src/components/views/ProfileScreen.tsx`:
   - Thêm xử lý map `ApiError` code `conflict` sang `t('plateAlreadyRegistered')` khi cập nhật xe.
4. `mobile/src/components/auth/LoginScreen.tsx`:
   - Thêm validation client-side cho `password.length < 8` khi đăng ký.
   - Thêm error handling thân thiện cho 422 validation_error và 409 conflict.

## 3. Quy trình xác thực sau khi sửa

1. **Kiểm tra cú pháp & kiểu dữ liệu**: Chạy `npm run lint` (`tsc --noEmit`) trong Docker node container.
2. **Kiểm tra unit tests**: Chạy `npm test` (`vitest run`) trong Docker node container.
3. **Kiểm tra build production**: Chạy `npm run build` (`vite build`) trong Docker node container.
4. **Kiểm tra tự động backend**: Chạy lại 107 test backend để bảo đảm không ảnh hưởng API.
5. **Kiểm tra trực quan trên browser (viewport mobile 390×844)**:
   - Thử thêm xe với biển số đã tồn tại khi app đang ở tiếng Việt → xác nhận thông báo hiển thị là tiếng Việt: *"Biển số xe đã được đăng ký trên hệ thống."* (DEFECT-MOBILE-01 đã fix).
   - Thử đăng ký với mật khẩu 5 ký tự → xác nhận thông báo hiển thị rõ ràng: *"Mật khẩu phải có ít nhất 8 ký tự"* thay vì "Request validation failed" (DEFECT-MOBILE-02 đã fix).
